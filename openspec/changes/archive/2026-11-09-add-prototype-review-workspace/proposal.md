# Proposal

## Why

现有 HTML 标注工作流不足以表达本项目需要的页面、状态、设备组合及共享设计系统。需要一个可安装到其他仓库的 npm 包，让 AI 编程客户端通过 MCP 启动本地交互评审站点，并在可追溯的反馈批次和预览版本之间持续迭代。

## What Changes

- 交付单一 npm 包，内含 CLI、stdio MCP、本地 HTTP 服务、已构建的浏览器工作区及技能资源；通过 MCP 按需启动目标项目的评审站点。
- 支持仓库内无需构建的 HTML/CSS/JS、多页面和本地资源，以清单组织“页面 → 状态 → 设备”的有效组合。
- 提供独立设计系统入口，展示令牌和组件；组件按设备查看，同页展示全部适用状态，页面尽可能复用同一组件及令牌。
- 提供预览按钮、默认元素评论、保存评论后在对话中主动要求 AI 更新、处理状态、用户复核与已解决评论归档。
- 将工作目录与已发布快照分离，AI 完成检查后统一发布，浏览器自动更新并尽可能恢复体验状态。
- 提供 MCP 指南资源及显式 Codex 技能安装命令；MCP Skills 扩展作为可选兼容增强，不作为基础使用前提。
- 支持配置监听地址、端口及浏览器访问地址，包括非 loopback 绑定。

## Capabilities

### New Capabilities

- `package-and-mcp`: npm 安装交付、CLI、项目绑定、MCP 工具、指南与本地技能安装。
- `prototype-catalog`: 页面、状态、设备清单、稳定入口、导航与原型运行约定。
- `design-system`: 令牌与组件展示、组件状态示例及页面复用关系。
- `review-feedback`: 定位评论、保存与处理快照、用户发起 AI 领取处理、持久化恢复及用户复核。
- `preview-revisions`: 本地服务、不可变预览版本、验证发布、自动更新及状态恢复。

### Modified Capabilities

无；当前没有已有规范或业务实现。

## Impact

- 新建 TypeScript 单包项目，具体源码、测试、构建产物、示例与文档目录在 design.md 中规划。
- 新增原型清单、原型桥接协议、HTTP/SSE 接口与 MCP 工具契约。
- 使用官方 MCP SDK、HTTP 服务库、SQLite 存储及浏览器验证工具；实施时锁定兼容版本，不引入云端 AI 调用。
- 用户设计源文件留在目标仓库，评论和快照写入独立运行目录；不依赖 Anno 或 Agentation。
- 不包含桌面 DPI/PPI/缩放仿真、原生系统窗口行为、云端托管、多人账号协作、框架开发服务器适配或无限后台唤醒 AI。

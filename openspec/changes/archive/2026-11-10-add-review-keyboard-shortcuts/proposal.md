# Proposal

## Why

反复切换预览、设备和页面状态时，用户需要不断离开画布操作控件。产品设计稿与实际工作区也存在连接状态位置、侧栏内容和控件行为等差异，需要在加入快捷键时统一，以审核过的设计稿作为实现依据。

## What Changes

- 非输入状态按 `C` 切换预览；`← / →` 切换设备，`↑ / ↓` 切换页面状态，使用当前清单的有效顺序与组合。
- 在预览按钮、设备与状态控件附近展示快捷键提示，保留鼠标操作；输入、中文输入法组合输入和原生控件操作不受干扰。
- 先更新 `design/` 的工作区和共享组件，演示快捷键及边界行为，在原有产品评审 session 发布设计稿供用户审核。
- 用户明确批准具体设计稿版本后，才能修改 `src/browser/` 中的实际工具实现。设计稿发布或任务完成不代表用户批准。
- 根据已批准设计稿同步实际工作区结构、连接状态、导航、提示、评论/归档交互及快捷键，使设计稿和实现可逐项对照验收。首轮反馈细化为：品牌移至左侧菜单底部，采用左图标、右侧中英文名称的组合，移除顶部横栏与外壳项目名称，连接状态在底部与品牌共用左侧对齐线，版本号移至预览按钮；删除独立快捷键说明区块，保留控件旁的按键提示。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `prototype-catalog`: 增加受上下文约束的预览、设备和状态快捷键，以及与下拉框一致的有效组合导航。
- `product-brand`: 增加可发现的快捷键提示、先审核设计稿的交付关口，以及产品设计稿与实际工作区的一致性验收。

## Impact

- 第一阶段：`design/pages/`、`design/components/`、相关组件展示、必要的 `design/manifest.json` 与 `tests/browser/product-design.mjs`，以及设计稿说明。
- 审核后第二阶段：`src/browser/workspace/`、样式和必要的 `src/browser/bridge/index.ts`、`src/contracts/bridge.ts`，相关浏览器/网关回归与文档。
- 保留现有九个 MCP 工具与发布方式；无需新依赖、数据库迁移或更改消费者项目的设计稿。
- 本轮仅创建规划文件，实际设计稿编辑在后续 apply 阶段进行；运行时实现另外受用户设计审核约束。

# Design

## Context

见 proposal.md 的动机。当前 `src/browser/workspace/main.ts` 已通过 choose、预览按钮和下拉框实现模式/组合切换，只有评论 Ctrl/Cmd+Enter 键盘处理；`renderCanvas` 根据 manifest 决定可用设备，历史版本禁用预览。iframe 键盘事件不会冒泡到外壳，现有桥接已校验 origin、source、frameId，并支持 opaque 网关 iframe。

`design/pages/app.js` 使用本地模拟状态，`design/components/ui.js` 的设备/状态选择器未完整反映当前状态；设计稿连接状态在侧栏底部，真实工具仍在头部，真实工具还保留设计稿已删去的署名/下一步区块。已有 product-design 和 review-editing 浏览器测试分别覆盖原型与真实外壳，可延伸为共同验收。

## Goals / Non-Goals

**Goals:** 建立先设计审核、后实现的两阶段工作流；共享用户可观察的键盘契约与验收矩阵；同步批准的工作区层次和现有评论操作。

**Non-Goals:** 不重做后端、MCP、数据库、消费者 demo 或品牌；不把设计稿的模拟内容写入实际工具；不改变现有发布和评论处理模型。

## Decisions

### 1. 分阶段且绑定具体审核版本

阶段 A 仅编辑 design/、设计稿验证及说明；通过现有 conversation 发布到原产品 session。评审在设计稿内部体验快捷键，外层工具在审核前保留旧行为。交付时明确区分内层原型与外层工具，避免用户在外层测试而误判。

在本变更记录审核 revision、用户明确批准的原话摘要和同步范围；未批准不得勾选审核关口，也不得修改 src/browser/、桥接契约或真实工具回归以实现新功能。阶段 B 才实现并对照验收。若用户修改设计要求，重新发布待审核版本；批准不自动覆盖后续新方案。创建提案本轮不启动阶段 A，后续 apply 从阶段 A 开始。

### 2. 快捷键适用范围与默认边界

| 按键 | 外壳非输入区 | 评论模式画布非输入区 | 体验模式画布非输入区 |
| --- | --- | --- | --- |
| C / Shift+C | 切换预览 | 切换预览 | 退出预览 |
| ← / → | 前/后设备 | 前/后设备 | 原型自身行为 |
| ↑ / ↓ | 前/后页面状态 | 前/后页面状态 | 原型自身行为 |

input、textarea、select、contenteditable（含子元素/继承）、具有文本或方向键交互语义的 ARIA 控件、输入法组合输入、defaultPrevented、Ctrl/Meta/Alt 修饰键和 repeat 全部放行。方向键不接受 Shift 修饰，保留选择等行为。已触发的快捷操作才 preventDefault；没有可操作目标不吞键。C 使用 key 小写判断，允许 Shift+C；状态首尾不循环。以上为待用户审核的明确默认方案。

不采用直接在整个 document 抢占所有键的方式，以保留原型表单、原生选择器、滑块和体验交互。现有 Ctrl/Cmd+Enter 保存逻辑独立保留。

### 3. 复用选择路径与合法组合

审核后提取小型动作/键盘判定函数，按钮、下拉框和快捷键走同一模式与 choose 路径，避免三套更新 URL、控件和 frame 状态的代码。设备顺序取实际显示的 manifest devices 顺序，状态顺序取 pages.states。状态回退明确使用与现有下拉框相同的目标 entries 首项，不在本次偷偷重排清单。

组件隐藏状态菜单，上下键无动作；左右键遍历存在示例的设备。令牌设备控件禁用，方向键无动作。历史模式以当前历史 manifest 为依据，只允许原有可用导航，C 不绕过禁用。导航继续遵守现有草稿保护，不能因快捷键额外丢失已保存评论或编辑草稿。

### 4. 跨 iframe 只转发有限动作

审核后扩展 bridge 的快捷动作消息：仅允许预览切换/前后设备/前后状态，不传管理 token、不接受任意选择对象或 URL。子 frame 先按输入/模式规则过滤，宿主再校验现有消息来源、frameId、合法动作和历史禁用规则；冒泡与转发不能重复执行。opaque 网关沿用现有严格 source/frameId 校验策略，不扩大接受来源。

设计稿阶段在原型自身模拟以上体验；不为使原型工作提前修改真实 bridge。完整跨域/网关验收放在审核后。

### 5. 可见提示与同步范围

预览按钮右侧放轻量 kbd C，设备/状态标签附近放成对方向键；补充屏幕阅读器可读的隐藏说明，移除独立说明区块；必要时在窄屏压缩控件提示并保留可读性。更新按钮文案时不能擦掉提示，隐藏状态控件也隐藏提示，状态选择必须正确反映当前值。

同步清单：工作区分区和单层导航；连接状态移至左下；已在设计稿删除的头像/全部评论入口/多余署名和下一步提示保持一致；设备/状态控件顺序、选中值与有效组合；预览提示；评论编辑/回复/快捷保存、归档与重开、历史横幅。核对设计稿中的归档按钮与真实独立 archive 语义，不能将所有归档模拟成确认修复。

根据首轮评论细化布局：移除顶部横栏，品牌位于左侧菜单底部，产品标志在左，中英文名称在右上下排列，连接状态在品牌上方左对齐，两行共用左右边界；版本号放入预览按钮，并提供可访问的版本描述。移除外壳头部和侧栏中的示例项目名称，保留底层项目身份与画布内品牌。此布局经用户审核通过，纳入阶段 B 的同步清单。

只同步已批准的产品结构和行为，不复制画布示例、项目数量、假连接状态、假评论或固定设备列表。需保留的真实工具运行信息融入审核设计，不直接删掉必要状态。

## Risks / Trade-offs

- [内外两层工作区快捷键冲突] → 阶段 A 明确在内层体验；阶段 B 验证单次动作、输入与预览焦点归属，必要时让嵌套交互控件处理事件优先。
- [单字符快捷键误触] → 限定工作区与非输入上下文、忽略输入法和长按，展示作用范围，保留按钮替代操作。
- [外观同步范围扩张] → 以上清单作为边界，截图加交互逐项核对，不扩展为新后端能力。
- [草稿或历史上下文被切换覆盖] → 重用现有动作路径，回归原位编辑、定位、归档重开与历史返回。

## Migration Plan

先发布设计稿并等待明确批准，再构建工具并执行回归；保留原 session、数据和不可变历史。设计稿可通过既有版本回退/重新发布恢复，工具代码可回退本变更，无需迁移数据库。关闭变更前记录批准 revision、桌面/窄屏对照结果、快捷键矩阵与已解释差异。

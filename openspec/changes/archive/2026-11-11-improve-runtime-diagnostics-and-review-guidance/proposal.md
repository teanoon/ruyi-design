# Proposal

## Why

项目包已升级至 0.3.0，但 MCP 握手仍报告写死的 0.1.0；目前缺少区分“同一会话恢复”与“后端进程已重启”的运行身份。另一方面，评论追加回复已能自动重开，技能与 MCP 文档仍要求用户手动重开，容易让 AI 给出过时指引。

## What Changes

- MCP 握手从启动时加载的包元数据取得真实版本，去除独立维护的版本常量。
- 在现有 start_review、get_review_context 和受认证 HTTP 上下文中增加只读 runtime 信息，提供包版本、进程实例 ID、PID 和启动时间；重启后实例变化，持久会话及历史保留。
- doctor 文本与 JSON 显示当前执行安装包的版本，明确它不代表已连接 MCP 进程的版本，并补充升级/重连核对步骤。
- 同步打包技能、MCP 指南与工具说明、用户文档和仓库自用技能：非空回复在非活动批次下自动重开，活动批次保持冻结、发布后留待下一轮；不再要求额外手动重开。
- 保留人工确认解决/归档、显式用户更新授权、九个 MCP 工具及三项资源，不增加监控、自动重启或新的设计界面。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `package-and-mcp`: 增加真实包版本与运行实例诊断契约，并使指南/技能交付准确反映既有评论行为。

## Impact

涉及 MCP 初始化及返回值、服务上下文、共享运行元数据、doctor 文本/JSON、打包技能及镜像、docs/mcp.md、docs/getting-started.md、迁移说明和相关测试。使用现有依赖；返回值仅增加字段，旧字段与工具名保持兼容。既有 review-feedback 规范已定义自动重开，本变更同步说明和验收，不修改其状态机。包版本提升、提交推送、发布和外部客户端配置不属于本次规划。

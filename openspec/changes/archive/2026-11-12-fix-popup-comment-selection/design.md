# Design

## Context

动机见 proposal.md。桥接层 `src/browser/bridge/index.ts` 将固定定位的高亮 div 加入 body，以最大 z-index 显示；悬停和 locate 共用 show 路径。原生 `showModal()` 和 Popover API 使用浏览器 top layer，普通文档层的 z-index 无法覆盖它们。现有 document 捕获监听器负责阻止原型交互并发送 selection，工作区收到后打开讨论或聚焦评论框。

探索中的 Chromium 最小实验确认了原生 dialog 内点击会发送 selection，宿主评论输入可以取得焦点。因此已确认的是高亮承载缺陷；不能把所有弹出层问题预先归因于点击丢失。现有评论和焦点浏览器测试未覆盖原生弹出层。starter 已包含 dialog 和自定义状态恢复接口，可参照其约定构造独立回归夹具。

## Goals / Non-Goals

**Goals:**
- 用同一高亮路径覆盖普通文档、模态 dialog 和 popover，包括恢复状态后的定位。
- 保留原型 DOM 身份、焦点交接、只读查看与已有组件高度测量行为。

**Non-Goals:**
- 不改变评论数据模型或桥接消息协议。
- 不新增自动打开任意弹窗的通用机制；继续使用现有状态恢复接口，无法恢复时沿用定位失败提示。
- 不支持浏览器原生 select 菜单、系统 alert 等不存在可选 DOM 子元素的系统界面。

## Decisions

### 1. 将高亮呈现到浏览器顶层

优先使用 `popover="manual"` 的非交互高亮承载，通过统一的显示/隐藏入口管理其顶层状态。显式重置 popover 默认 margin、inset、padding、背景与尺寸约束，沿用视口坐标；设置 pointer-events:none、不可聚焦和辅助技术隐藏，避免默认 backdrop 拦截指针。不得调用 showModal 创建评论辅助层。

显示时依据真实目标解析所属活动模态容器：在模态场景下让辅助层处于可交互 dialog 的 DOM 子树内，避免落入模态 inert 区域；普通页面和 popover 场景保留文档级承载。只移动辅助节点，不移动或复制原型元素。针对新打开的顶层弹窗重新提升辅助层的顶层顺序；避免每次 pointermove 都执行隐藏/显示。

只提高 z-index 无法突破 top layer；仅将普通 div 放入 dialog 又可能受其裁剪和坐标系影响。单独在工作区画高亮则需额外处理 iframe 缩放、滚动与组件高度，因此采用桥接内部的顶层承载。能力检测不支持 Popover API 时，使用目标活动 dialog 内的非交互高亮或普通文档高亮作为降级，单独验证其可用范围，不将不受支持环境的降级视作完整顶层保证。

### 2. 统一悬停、选择及定位生命周期

高亮入口接收目标元素及其视口矩形，使 hover 和 locate 可选择正确承载。点击选择同时刷新目标高亮，覆盖无 hover 的触摸场景。保持从实际事件目标生成 selector/reviewId 和上下文；辅助节点不参与锚点、字段采集或组件高度测量。

模式切换、Escape、定位失败统一隐藏并退出辅助 popover。目标所在弹窗关闭、目标移除时清理悬空高亮；用弹出层生命周期事件或有过滤的观察处理，不引入常驻逐帧轮询，防止观察自身样式变更形成循环。组件测量继续排除标记的辅助节点。

### 3. 保留事件契约，以回归区分问题

沿用 document 捕获阶段阻止 pointerdown 默认行为和 click 原型处理，不先行扩大到全局事件拦截。通过真实浏览器点击检查 selection 的锚点、按钮动作计数、弹窗 open 状态及评论框持续输入；若测试复现特定点击路径丢失，仅在该路径补充最小修复。

新增 `tests/browser/popup-comments.mjs` 和 `test:popup-comments` 入口，使用临时设计目录及 ReviewServer，覆盖原生 dialog、popover、普通高 z-index DOM 弹层和叠加 dialog。在桌面与窄屏画布中验证真实点击、保存、同元素讨论复用、状态恢复后的 locate，以及预览开关行为。

高亮验证必须证明实际绘制在目标上方：使用受控纯色夹具的截图边框像素断言或等价遮挡检查，同时断言矩形对齐；仅检查 display、DOM 存在或 Playwright isVisible 不足以捕捉本缺陷。测试保留失败截图以便定位。

## Risks / Trade-offs

- [模态 inert 与顶层顺序影响辅助 popover] → 覆盖已有模态、新开模态、叠加模态及关闭后重新选取，确保不关闭用户弹窗、不夺取焦点。
- [设计稿通用 CSS 覆盖 popover 默认样式] → 对辅助节点显式设置关键呈现属性，使用带通用弹层样式的夹具验证。
- [移动辅助节点改变无 id 元素的结构选择器或测量结果] → 只追加辅助节点、保留实际目标 DOM，并验证无稳定 id 元素的锚点及组件高度不变。
- [修改高亮路径影响删除标记、只读定位或 region 内部模式] → 保留原有样式参数和坐标契约，执行已有定位、删除及焦点回归。
- [不同浏览器的 Popover API 支持程度不同] → 能力检测并提供降级；本次自动化验收以项目现有 Chromium 基线为准，不新增浏览器依赖。

## Migration Plan

无需数据迁移。重新构建桥接脚本随包交付；撤销桥接代码与测试入口即可回退，不改变已有评论记录。发布、版本提升和提交按项目收尾约定另行获得授权。

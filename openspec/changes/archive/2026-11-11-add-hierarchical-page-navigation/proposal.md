# Proposal

## Why

当系统包含 10 个菜单、每个菜单包含 5 个业务 Tab 时，现有单层页面列表需要展示约 50 个入口，难以浏览和定位。菜单本身也可能是一个需要独立评审的概览页，需要支持父页面与子页面同时存在。

## What Changes

- 页面导航支持可折叠的层级结构；节点可以是页面、包含子节点的父页面或纯分组。
- 父页面名称打开自身页面，独立箭头展开/收起子节点；打开页面不改变展开状态，折叠不切换画布。
- 支持当前页面与祖先提示、展开状态记忆、搜索，以及深链接和评论跳转时展开定位。
- 保留平铺的页面定义和稳定页面 ID，新增可选导航结构；未提供结构的旧清单继续平铺显示。
- 页面状态和设备继续在内容区选择，业务 Tab 可以作为独立页面，不新增 Tab 专属导航维度。
- 导航节点用关闭文件夹、打开文件夹和单页图标区分，选中/悬停高亮覆盖整行，根级图文与设计系统对齐；提供可直接进入的首页子页面展开状态。
- 评论只精确匹配同一元素，支持同元素多条评论；取消编辑保留原文，归档或解决不切换标签，用户追加回复默认重新打开。
- 评论模式保护外层输入焦点，预览模式保留原型控件交互。
- 标志去除白色底板和外围留白；品牌文字下方以纯文字状态胶囊替换英文副标题。
- 同步产品原型、资产契约、生成 schema、示例与实际工作区，替换相关文档中的旧导航、品牌及评论约束。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `prototype-catalog`: 将单层页面导航改为兼容旧清单的层级导航，定义导航结构校验、父页面交互、搜索、展开恢复与定位行为。
- `product-brand`: 调整单层导航约束，定义透明紧裁标志、状态胶囊、准确元素编辑与最终设计/实现对齐。
- `review-feedback`: 补充精确元素评论、多条评论、取消编辑、归档标签保持及追加回复自动重新打开，保留固定处理输入和历史。

## Impact

- 清单及校验：`src/contracts/catalog.ts`、`src/core/catalog/index.ts`、生成的 `schemas/manifest.schema.json`；导航引用随版本快照保存，不改变评论 Target 或组合枚举身份。
- 工作区：`src/browser/workspace/main.ts`、工作区 HTML/CSS、快捷键焦点保护及历史版本导航。
- 产品原型：`design/components/`、相关工作区脚本和清单；保留组件总览与令牌入口。
- 分发与说明：`docs/asset-contract.md`、`docs/brand-guidelines.md`、MCP 清单资源/模板、打包的资产指南与示例。
- 反馈服务：`src/core/feedback/index.ts`；追加回复的状态变化持久化，队列/处理中的追加内容在发布后保留为下一轮输入。
- 验证：清单校验单元测试及真实浏览器导航、评论定位、历史版本和快捷键回归；无需引入 UI 组件库或修改存储数据库。

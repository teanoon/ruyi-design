# Design

## Context

动机见 proposal.md。变更前 `manifestSchema` 只有平铺的 `pages`，`renderNav()` 按数组顺序生成按钮；`choose()`、URL、组合枚举与评论 Target 使用页面 ID、状态 ID 和设备 ID。版本快照保存 manifest，工作区通过 `displayedRevision()` 在最新与历史清单间切换。`prototype-catalog` 和 `product-brand` 均包含单层导航约束，本变更同步修改这两个契约。

## Goals / Non-Goals

**Goals:** 将导航层级与页面身份分离；同一节点支持独立的页面选择和折叠；明确未归组页面、搜索、历史版本和焦点行为，避免实现时临时决定。

**Non-Goals:** 本次不提供拖拽排序、可视化目录编辑器、多位置页面别名、页面权限或组件/令牌层级改造；不把业务 Tab 统一转换为页面状态，不引入数据库迁移。

## Decisions

### 1. 可选导航树引用平铺页面

在 schemaVersion 1 下新增可选 `pageNavigation` 数组，节点包含稳定 `id`、可选 `pageId`、可选 `name` 及可选 `children`。示例：

```json
{
  "pageNavigation": [
    {
      "id": "orders-nav",
      "pageId": "orders",
      "children": [
        { "id": "orders-pending-nav", "pageId": "orders-pending" }
      ]
    },
    {
      "id": "administration-nav",
      "name": "系统管理",
      "children": [
        { "id": "users-nav", "pageId": "users" }
      ]
    }
  ]
}
```

页面节点名称默认取对应 `pages` 的 name，非空 name 可覆盖导航展示名；纯分组必须有非空 name 和至少一个子节点。节点必须引用页面或具有子节点。节点 ID 在整棵树内唯一，页面引用必须存在，同一页面不能被引用多次；内嵌 children 不使用父引用，因此 JSON 输入不会形成环。支持递归层级，创作指南建议两到三级，不设只允许两层的业务限制。

未配置或配置为空树时按 pages 顺序平铺；部分配置时，未被引用的页面按 pages 顺序追加至根级，避免添加页面后入口消失。页面总数只统计 pages，分组数量和导航节点数不计入；分组右侧数量为后代页面数，不包括父节点自身页面。

替代方案：在 pages 中加 parentId 会将纯分组混入页面定义；递归嵌套 pages 会影响现有评论和组合遍历。独立导航树可保留当前调用契约。新增字段保证新版本读取旧清单；旧运行时不承诺识别新导航，发布说明应指出升级后生效。

### 2. 同行独立控件，明确选择与展开

带子节点的行使用两个同级控件：文件夹图标按钮修改展开状态；有 pageId 的名称按钮调用现有页面选择逻辑，设备选择遵循原有有效组合回退规则。纯分组名称与文件夹图标均执行折叠，不产生不存在的页面 Target。叶子页面使用单页图标，不提供折叠操作。

只对当前页面名称标记 aria-current；选中与悬停高亮覆盖包含图标和名称的整行，根级图文与设计系统入口对齐；祖先显示单独的后代选中提示，不冒充选中页面。折叠当前页的祖先允许继续显示当前画布，箭头操作不触发 iframe 重建、URL 写入或评论草稿变化。名称点击不自动展开其子树，也不创建额外“概览”。

替代方案是整行点击同时打开并展开，但它会让用户无法只查看概览或只整理目录，故拆分点击区域。

### 3. 用户展开状态与定位展开分离

维护按项目 manifest.id 和节点 ID 区分的展开偏好，存入带产品命名空间的浏览器 localStorage；同源项目必须使用独立 manifest.id。只保存导航偏好，不写入 manifest 或评审数据。存储不可用时退化为本次工作区内记忆。

初次进入时未记忆的分组默认折叠，当前页面祖先自动展开。URL/浏览器历史恢复、评论定位、进入或退出历史版本及新发布版本切换时，使用所显示版本的导航树展开并滚动定位当前页；必要时这次定位覆盖祖先的折叠偏好，但不重写其他分组偏好。普通重绘或点击箭头不强制重开当前页祖先。不同历史版本只应用仍存在的节点偏好，不改写不可变快照；不存在的页面沿用当前的缺失入口提示与回退。

替代方案是每次 renderNav 都强制展开选中祖先，会导致用户无法收起当前目录，因此显式区分定位事件与普通渲染。

### 4. 搜索为临时导航视图

页面区提供搜索输入框。忽略首尾空白与英文大小写，按页面实际名称、导航展示名和祖先名称进行子串匹配；分组名称匹配时保留其后代页面。结果保持树中原顺序和祖先路径，相关路径临时展开；无结果给出明确文本。选择结果只切换页面，保留查询方便继续比较；清空查询恢复搜索前的展开偏好。页面总数不因筛选变化。

从 URL、评论或版本切换主动定位页面时清除搜索，避免目标因筛选隐藏。搜索期间的路径展开不写入长期偏好。搜索采用本地过滤，50 页规模无需引入虚拟列表或远端索引。

### 5. 使用嵌套列表与原生按钮，避免混用 tree 语义

导航使用嵌套列表、页面按钮与带 aria-expanded/aria-controls 和可访问名称的折叠按钮。不声明 ARIA tree，也不引入额外的方向键树导航协议。Tab 按可见控件顺序移动，Enter/Space 激活对应操作；收起含焦点的子树时将焦点放回该分组箭头。导航内方向键不触发工作区设备/状态快捷键；输入搜索时保留编辑行为，外部画布和工作区快捷键继续按原契约执行。

焦点恢复以节点 ID 和操作类型标识，避免现有 replaceChildren 重绘丢失焦点。窄屏通过缩进和可换行名称控制宽度，不依赖悬浮才能发现操作。

### 6. 同步产品原型与分发契约

导航解析、搜索、展开记忆和 DOM 控件共用 `design/components/page-navigation.js` 及 CSS；原型直接以 ES module 使用，真实工作区通过 Vite 打包，配套声明文件供 TypeScript 检查。服务端只依赖清单类型及校验，不从 design 目录加载运行时文件，因此发布包无需携带产品原型源文件。更新产品原型共享 navigation 组件及其工作区交互，使用父页面和纯分组混合示例验证；真实浏览器测试另外生成 10 个父页面、每个 5 个子页面的清单，共 60 个页面，避免例子低估父页面数量。产品原型无需将 60 个模拟页面写进自身评审 manifest。

实现后重新导出 schema，检查 MCP 提供的 schema/template 与打包资产指南是否包含新能力，更新资产契约和品牌指南。保持 starter 原有平铺清单可运行，并在说明中增加层级示例。快捷键原有审核记录保留；本次评审追加的导航、品牌和评论调整以最终批准版本为准。

### 7. 精确评论、取消和多条反馈

同一对象/状态/设备内，只在双方具有 reviewId 且相等、或没有双方标识但完整 selector 相等时匹配同一元素，不再把父子关系视为同一元素。默认再次选择打开已有评论，卡片的“新增评论”显式创建同元素的新记录。取消只清除本次输入与编辑展示并重绘正文，不修改保存内容；归档与确认解决保留当前标签页。元素评论模式在 pointerdown 阶段拦截原型默认焦点及处理器，预览模式继续保留表单交互。

### 8. 追加回复默认重开与固定输入隔离

非活动批次内的用户非空回复将评论转为 draft，保留原文、定位、历史结果与线程；浏览器显示进行中。队列/处理中的回复只追加线程，不修改固定输入。发布时比较固定快照后的用户线程，若存在新增回复，则在记录本轮结果后将评论保留为 draft，等待下一次用户主动请求处理。代理处理线程不触发重开。

为兼容仍常驻旧模块的 MCP 进程，浏览器在旧服务未自动重开且没有活动批次时补充 reopen 请求；新服务直接返回 draft，不重复调用。此兼容处理不改变后台固定输入保护，也不自动发起 AI。重启后的服务已完成核验。

### 9. 最终品牌与连接胶囊

标准与单色标志 viewBox 紧裁至方印边界，去掉外围白底，保持既定图案和透明圆角；favicon 增加资源版本参数避免旧缓存。品牌底部左侧标志、右侧中文名称，下方由纯文字状态胶囊替换英文副标题。胶囊没有图标、状态点或额外状态行，继续通过 role=status 传达连接、处理、重连和失败状态。原型与工作区共用 connection-status.css。

## Risks / Trade-offs

- [递归层级过深挤压窄屏] → 建议两到三级，名称换行并验证无横向溢出。
- [重绘导致展开或焦点重置] → 将偏好、搜索临时视图和页面选择分离，使用稳定节点 ID 恢复焦点。
- [目录整理影响历史评论] → 页面 ID 不变，定位只使用所显示版本的树，覆盖移动页面与历史跳转回归。
- [部分导航配置遗漏页面] → 未引用页面自动追加根级；对错误引用及重复引用明确报错。
- [旧客户端忽略新字段] → 兼容承诺限定为新版本读取旧清单，文档说明层级导航需要升级工作区。

## Migration Plan

1. 先扩展可选清单结构及校验、导出 schema，保留无配置回退。
2. 在产品原型中表达并验证交互，再同步工作区渲染、搜索、定位和偏好恢复。
3. 更新指南与示例，完成单元及浏览器验收后发布；已有项目无需迁移。
4. 回退时可移除 pageNavigation 恢复平铺导航；页面、评论和历史快照无需改写，旧快照继续按其原有清单显示。

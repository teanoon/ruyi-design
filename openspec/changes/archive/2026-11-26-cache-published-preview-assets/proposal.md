# Proposal

## Why

切换独立原型页面时，浏览器会加载目标 HTML。原有的 `no-store` 策略使已经访问过的 HTML 和共用的静态资源仍可能重复传输。同一页面的状态如果通过重建 iframe 切换，也会重复请求文档并初始化页面。

通过局域网 IP 或普通域名用 HTTP 访问时，工作区创建 iframe 和原型桥接脚本发送快捷键都会调用浏览器可能不提供的 `crypto.randomUUID()`，导致加载或交互失败。

## What Changes

- 对已发布快照中的版本化 CSS、JavaScript、字体和图片启用浏览器私有缓存，覆盖直连预览和单入口网关。
- 四个 Starter 页面各用一个 HTML 入口，跨页导航按清单加载目标文档。工作区请求的已发布原型 HTML 在符合条件时可私有缓存 60 秒，过期后使用 `ETag` 校验。
- 为注入的桥接脚本 URL 加入构建产物的内容指纹。同一份桥接脚本可在不同原型页面间复用，脚本内容更新时使用新地址。
- 工作区 HTML、未带有效指纹的桥接脚本、评审 API 和未发布候选使用 `no-store`。状态入口按清单初始化，评论关联对应的状态和版本。
- 用真实浏览器验证往返切换时共用资源命中缓存，并验证发布新版本后加载更新后的资源。分别记录直连和网关的切换耗时。
- 工作区与桥接脚本共用兼容的 UUID 生成逻辑，使普通 HTTP 下也能加载和切换原型，并使用原型内快捷键。
- 支持原型显式接入同页状态原地切换。工作区在同一版本、页面、设备和 HTML 入口内复用已经加载的 iframe，并同步状态直达链接和评论目标。未接入的原型和不同入口沿用正常加载流程。
- Starter 登录、工作台、项目详情和设置均接入原地切换。在桌面和移动端逐页验证同页状态往返时新增 HTML 文档请求为零，同时覆盖直达链接、评论定位和回退。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `preview-revisions` 增加已发布预览资源和原型 HTML 的私有缓存、版本隔离、普通 HTTP 兼容及可选的同页状态切换要求。

## Impact

- `src/server/index.ts` 的预览资源响应和 `/_preview/` 网关响应。
- 工作区状态导航、原型桥接消息及浏览器端 UUID 调用。
- Starter 的四个页面及原型资源契约说明。
- 服务端响应测试、Playwright 缓存和同页状态切换、版本发布及普通 HTTP 快捷键回归。

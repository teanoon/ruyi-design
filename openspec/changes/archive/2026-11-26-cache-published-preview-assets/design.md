# Design

## Context

`src/server/index.ts` 的预览路由从持久化版本和验证候选中查找快照。网关通过同一路由获取资源，按入口改写 CSS、JavaScript 和 HTML，再将响应转发给浏览器。HTML 还会注入工作区来源和会话 ID。

工作区用浏览器 UUID 标识 iframe，桥接脚本用浏览器 UUID 标识快捷键消息以便去重。普通非回环 HTTP 页面可使用 `crypto.getRandomValues()`，但浏览器只在安全上下文提供 `crypto.randomUUID()`。

## Goals / Non-Goals

直连和网关按同一规则复用已发布的资源响应。跨页导航加载清单指定的独立文档，可以命中已访问入口的 HTML 缓存。已接入的同页同入口状态可在普通 HTTP 下复用 iframe，原型直达链接能独立初始化。

## Decisions

1. 在预览资源路由保留 `no-store` 默认值，成功读出并处理完资源后，再根据已发布记录与扩展名白名单设置 `Cache-Control: private, max-age=3600, immutable`。白名单覆盖快照支持的 CSS、JavaScript、字体和图片格式。已发布的历史快照适用相同规则。私有缓存允许浏览器直接复用新鲜响应，同时禁止共享代理存储。一小时的有效期控制浏览器能够直接复用响应的时间。
2. 单入口网关转发预览路由生成的 `Cache-Control`，使用请求中的完整资源地址作为浏览器缓存键。快照版本 ID 隔离不同发布版本，网关的查询参数区分外部路由。
3. 以真实浏览器的资源缓存命中及页面状态断言为验收依据。比较打开状态至关键 UI 可操作的耗时，记录样本供评估。缓存命中和资源内容使用确定性断言，耗时以测量结果报告。
4. 工作区和桥接脚本共用浏览器端 UUID 生成函数。原生 `crypto.randomUUID()` 可用时直接调用，否则用 `crypto.getRandomValues()` 生成 16 字节并按 UUID v4 设置版本和变体位。两条路径产生同样的 UUID 格式，继续使用现有的消息标识、来源与窗口校验。服务端 Node.js UUID 调用沿用现有 API。
5. 原型可注册 `window.ruyiDesignApplyState`，以状态 ID、清单查询参数和 hash 接收入口。桥接脚本在就绪时报告能力，首次打开入口仍由原型按 URL 初始化。Starter 的登录、工作台、项目详情和设置各自用同一个入口函数处理首次和后续状态，重置表单、对话框、任务、筛选或待执行跳转等各页面的状态相关副作用。
6. 状态下拉框和快捷键复用同一个切换入口。工作区确认当前 iframe 已就绪，且源和目标的版本、页面、设备与 HTML 路径一致后，通过现有来源、窗口和 iframe 标识校验的消息通道发出带请求 ID 的切换指令。桥接脚本检查当前文档仍是所声明的入口，避免把已在原型内导航到其他页面的 iframe 当成可复用文档。生效确认后，工作区更新状态控件、可分享的 URL、快捷键和评论目标。
7. 桥接脚本用已确认的入口参数提供评论和版本恢复所需的路由上下文，兼容无法用 History API 改写内部 URL 的网关沙箱。应用期间忽略该 iframe 的新元素选择。失败、超时或更晚的导航替换当前切换时，按最新选择执行现有加载流程，并丢弃过期回执。首次打开直达链接、不同文档、未接入的旧原型及需要恢复上下文的评论定位继续正常加载声明入口。
8. 仅当 HTML 属于已发布快照，且 URL 参数 `__ruyi_html_cache` 匹配当前服务的缓存标识时，使用 `private, max-age=60, must-revalidate`。工作区从已认证的会话上下文获取标识，并使用它构造 iframe 地址。服务每次启动生成新标识。版本 ID、外部预览地址、完整查询参数和服务标识共同隔离浏览器缓存。清单已占用该参数时保留清单值，该入口走常规加载。原型资源可读取标识，它不参与鉴权。桥接脚本从评论与状态捕获 URL 中移除它。
9. 基于已注入桥接配置、完成网关改写的实际 HTML 生成弱 `ETag`。访问检查通过后再匹配 `If-None-Match`，一致时返回无正文的 `304`。网关转发条件请求头、`ETag` 和缓存控制。只有短时复用已缓存的完整文档时才省去网络请求，切换独立入口仍运行文档初始化代码。
10. 每个服务实例首次需要桥接脚本时读取构建产物，并计算一次 SHA-256。注入的脚本 URL 使用该指纹，直连和网关仅在指纹匹配时返回一小时私有不可变缓存。会话配置由原型 HTML 内联提供。旧 HTML 引用的无指纹或过期指纹地址仍可获取当前脚本，并使用 `no-store`。启动新服务实例时读取当前构建产物。

## Risks / Trade-offs

- 若测试代理漏转缓存头，网关浏览器无法复用资源。让测试代理转发该头，并断言浏览器收到的值和实际缓存命中。
- 即使共享资源命中缓存，重新执行脚本和渲染仍可能占据主要耗时。分别观察资源传输和原型可操作时间。
- 编辑源文件后，浏览器会继续使用对应已发布快照的旧资源。通过正式发布生成新 revision URL，并验证新旧版本分别加载各自的内容。
- HTML 的桥接配置依赖启动时的工作区地址和会话。浏览器通过新服务标识取得新缓存地址，旧地址返回当前 HTML 并要求不缓存。
- 本机回环 HTTP 是浏览器的安全上下文例外，可能只测到原生 UUID 路径。用浏览器实际判定为非安全上下文的 HTTP 地址做回归，并在工作区和原型 iframe 中断言 `crypto.randomUUID()` 缺失。
- 快速切换可能与异步原型渲染、版本切换或评论定位重叠。用请求身份约束提交结果，并验证旧回复不会覆盖最新选择或改变已有评论的目标。
